01 / SINGLE REQUEST

Keep the path simple.

One application instance handles the request. Redis can serve hot eligibility and upcoming-bonus reads; PostgreSQL remains the durable source of truth.

WHAT CHANGES AT THIS SCALE

  • One service instance is enough for the illustrative starting point.
  • Redis avoids repeatedly hitting PostgreSQL for hot read data.
  • Lifecycle writes remain durable in PostgreSQL; events can be processed asynchronously.
01 / READ

Eligibility and upcoming-bonus reads check Redis first; cache misses fall back to PostgreSQL.

02 / WRITE

Bonus lifecycle changes are persisted durably in PostgreSQL. Redis supports fast access to hot data.

03 / PROCESS

Kafka provides an asynchronous event path for downstream consumers and reporting workflows.

*10M+ RPM transaction metric is the scale figure already stated in this portfolio. The user selector is an architecture walkthrough—not a live benchmark or a claim that these exact node counts were deployed. Redis accelerates the hot path; it is not presented as the durable transaction ledger. Actual capacity depends on workload mix, data model, cache hit rate and load testing.
